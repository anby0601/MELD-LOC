# Cohort tables

One table per role, one row per simulation run, with the recipe that produced it. `SUMMARY.md`
holds the counts and consistency checks of the last build.

| table | runs | content | read by |
|---|---|---|---|
| `development.csv` | 255 | training and development-validation cohort (`split_role` = train / validation); 237 runs are in the frozen feature cache (`frozen_cache` = 1), see below | `models/features/build_features.py`, `datagen/generate_development.sh` |
| `holdout.csv` | 24 | in-route holdout, routeA, replicates r51/r52 | `datagen/generate_holdout.sh`; the evaluation reads `data/logs/holdout/ledger.csv` |
| `crossroute.csv` | 20 | cross-route evaluation, routeB / Town02 | `datagen/generate_crossroute.sh`; evaluation via `data/logs/crossroute/ledger.csv` |
| `stress.csv` | 20 | evaluation-only stress runs: speed profiles and high-intensity recipes | `datagen/generate_stress.sh`; evaluation via `data/logs/stress/ledger.csv` |
| `ndt_covariance.csv` | 15 | holdout recipes with the matcher's Hessian (Laplace) covariance output enabled | `datagen/generate_ndt_covariance.sh`; evaluation via `data/logs/ndt_covariance/ledger.csv` |

Row order of `development.csv` is the order in which the feature pipeline visits the runs
(it is part of the feature cache); do not re-sort it.

## Columns

| column | meaning |
|---|---|
| `scenario_id` | recipe name; one recipe can appear with several replicates, profiles or covariance options |
| `role` | the table the row belongs to |
| `route` | `routeA` (Town01) or `routeB` (Town02, independently built map) |
| `family` | degradation family; `healthy` = undegraded run |
| `mode`, `schedule`, `sector`, `seed` | perturbation-node arguments exactly as executed; `schedule` = `route_progress_m:intensity,...` |
| `profile` | speed profile `std` / `fast` / `aggr` |
| `covtype` | NDT covariance option `fixed` (default) or a `laplace*` variant |
| `replicate` | replicate index (holdout and cross-route r51/r52, stress and covariance runs r60-r62) |
| `split_role` | development cohort: `train` or `validation` |
| `cluster_id`, `recipe_group_id` | the recipe-group unit used for cross-validation folds, calibration and bootstrap resampling (`recipe_group_id` where recorded, otherwise `cluster_id`) |
| `run_status` | `VALID_COMPLETED` or `VALID_COLLAPSE` (a valid run that ended in localization divergence; these runs are the main source of large-error anchors) |
| `frozen_cache` | development cohort: `1` if the run is part of the frozen feature cache, `0` for the 18 runs (12 translate_y, 6 sector_thin) whose log directories were not reachable by the pipeline when the cache was frozen. Their logs were recovered later and are shipped, but the frozen models and every result file were produced without them; `build_features.py` skips them unless `--all` is given, so that the rebuilt cache equals the frozen one |
| `raw_run_dir` | run directory `data/logs/<role>/<run>` (from the data archive, or regenerated by the `datagen/` scripts) |
